# Fear & Greed Telegram bot

Бот раз в N часов (по умолчанию 4) берёт Crypto Fear & Greed Index и пишет в Telegram, когда индекс
доходит до заданных уровней страха или жадности. Повторные уведомления подавляются: по одной стороне
(fear/greed) не чаще раза в `cooldown` (по умолчанию 2 дня).

Один статический бинарник около 7 МБ, из зависимостей только YAML-парсер.

## Откуда берутся данные

Источник задаётся ключом `source` в конфиге.

**`alternative` (по умолчанию)**: [alternative.me](https://alternative.me/crypto/fear-and-greed-index/),
официальный бесплатный API без ключа: `GET https://api.alternative.me/fng/?limit=1`
([internal/alternative](internal/alternative)). Индекс обновляется раз в сутки (в 00:00 UTC).
Правила API требуют указывать источник рядом с данными, поэтому в каждом сообщении бота есть строка
«Данные alternative.me на …» со ссылкой.

**`coinglass`**: [индекс CoinGlass](https://www.coinglass.com/pro/i/FearGreedIndex). Их официальный API
(`open-api-v4.coinglass.com/api/index/fear-greed-history`) требует ключ `CG-API-KEY` и доступен только
на платных тарифах, поэтому бот читает данные страницы. В HTML значения нет: браузер загружает его
JavaScript-ом из `capi.coinglass.com/api/index/history`, и ответ зашифрован (AES-ECB + zlib, ключ
выводится из заголовков ответа). Бот делает тот же запрос, что и страница, и расшифровывает ответ
тем же алгоритмом, что и её JS ([internal/coinglass](internal/coinglass)). Способ неофициальный:
если сайт поменяет шифрование, бот перестанет его читать (см. ниже). Индекс обновляется раз в сутки
(около 00:20 UTC).

Это два разных индекса с разной методикой и разными границами зон (Fear, Greed и т. д.), поэтому
значения у источников не совпадают. При смене источника стоит перепроверить пороги.

## Быстрый старт

1. Создайте бота у [@BotFather](https://t.me/BotFather) и получите токен.
2. Узнайте `chat_id`: напишите боту любое сообщение и откройте
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates`, нужное поле `chat.id`. Для канала подойдёт `@имя_канала`,
   бот должен быть администратором канала.
3. Настройте конфиг:
   ```bash
   cp config.example.yaml config.yaml
   ```
4. Соберите бота и проверьте связку «источник индекса → Telegram»:
   ```bash
   make build
   ./fngbot -config config.yaml -test-message
   ```
5. Запустите:
   ```bash
   ./fngbot -config config.yaml
   ```

Флаги:

| Флаг | Что делает |
|---|---|
| `-config path` | путь к конфигу, по умолчанию `config.yaml` |
| `-once` | одна проверка и выход, без сообщения о старте; удобно для cron |
| `-test-message` | отправить в Telegram текущее значение индекса и выйти |

## Конфигурация

Все параметры с комментариями описаны в [config.example.yaml](config.example.yaml).

```yaml
source: alternative   # alternative (alternative.me) или coinglass
interval: 4h          # как часто проверять; понимает и дни: 1d, 1d12h
alerts:
  fear: [20]          # уведомить, если индекс <= 20
  greed: [80]         # уведомить, если индекс >= 80
dedup:
  cooldown: 2d        # не чаще раза в 2 дня по каждой стороне
  storage: file       # file (переживает рестарт) или memory
  file: data/state.json
telegram:
  bot_token: "..."    # или переменная окружения TELEGRAM_BOT_TOKEN
  chat_id: "..."      # или TELEGRAM_CHAT_ID
```

Переменные окружения `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` имеют приоритет над файлом,
так что секреты можно в конфиге не хранить. Опечатки в ключах конфига считаются ошибкой.

## Когда приходит уведомление

- При запуске (без `-once`) бот сразу проверяет индекс и присылает сообщение о старте: текущее
  значение, пороги, время следующей проверки и паузу между повторами. По текущему значению видно,
  что источник читается правильно; его можно сверить с сайтом. Если индекс получить не удалось,
  вместо значения в сообщении будет ошибка. Алерт по первой проверке, если он нужен, приходит
  следом. Если Telegram в этот момент недоступен, бот пишет предупреждение в лог и продолжает работу.
- Уровни включительные: `fear: [20]` срабатывает при индексе 20 и ниже, `greed: [80]` при 80 и выше.
- На каждую сторону можно задать несколько уровней (`fear: [25, 10]`). В уведомлении указывается
  самый глубокий достигнутый уровень.
- Cooldown считается отдельно для страха и для жадности: если рынок резко развернулся, вы об этом узнаете.
- В пределах cooldown повторов нет. Исключение: индекс дошёл до более глубокого уровня той же стороны
  (например, после уведомления о `≤ 25` индекс упал до `≤ 10`). Откат назад к `≤ 25` новое
  уведомление не вызывает.
- Время последней отправки хранится в JSON-файле (`dedup.file`). Файл пишется атомарно, поэтому
  перезапуск или запуск через cron с `-once` не приводит к повторной отправке.
- Если Telegram или источник индекса недоступны, проверка повторяется через 5 минут, а не через
  `interval`. Неотправленное уведомление не запускает cooldown.

Сообщение о старте:

```
🚀 Fear & Greed бот запущен

Индекс сейчас: 71 (Greed)
Данные alternative.me на 25.09.2026 00:00 UTC

Пороги:
😱 страх: ≤ 20
🤑 жадность: ≥ 80

Проверка индекса: с интервалом 4 часа, следующая 25.09.2026 18:48 UTC
Пауза между повторными уведомлениями: 2 дня
```

Уведомление о пороге:

```
😱 Fear & Greed Index: 18 (Extreme Fear)
Достигнут ключевой уровень страха: ≤ 20
Данные alternative.me на 25.09.2026 00:00 UTC
```

«alternative.me» в сообщениях — ссылка на страницу индекса. С `source: coinglass` там будет
CoinGlass, а перед этой строкой ещё и цена BTC.

## Docker

```bash
cp config.example.yaml config.yaml      # секреты можно оставить пустыми
printf 'TELEGRAM_BOT_TOKEN=...\nTELEGRAM_CHAT_ID=...\n' > .env
docker compose up -d --build
```

Образ собирается `FROM scratch` и содержит только бинарник и CA-сертификаты. Процесс работает
от пользователя `nobody`, поэтому `config.yaml` должен быть доступен на чтение всем (`chmod 644`),
а секреты лучше передавать через `.env`. Состояние дедупликации хранится в томе `fngbot-data`.

## Тесты

```bash
make test        # go test -race ./...
make test-live   # по одному реальному запросу к alternative.me и coinglass.com
```

Unit-тесты работают без сети: источники индекса и Telegram подменяются локальными
`httptest`-серверами. Покрыты:

- оба клиента: ответы, ошибки API и HTTP; для CoinGlass ещё и расшифровка всех известных версий `v`;
- пороги, cooldown и эскалация;
- файловое хранилище: рестарт, атомарная запись, битый файл;
- клиент Telegram, в том числе то, что токен не попадает в логи;
- разбор конфига;
- сквозные сценарии `main`: стартовое сообщение, алерт после него, повторные запуски через `-once`.

Разбор ответов проверяется на реальных ответах обоих источников из [testdata](testdata):

- **alternative.me, 25.09.2026**: бот получает 71 (Greed) на 25.09.2026 00:00 UTC.
- **CoinGlass, 24.09.2026**: страница тогда показывала 72 (Greed), и бот получает то же значение,
  дату и цену BTC. Проверяется и вся история: первый график действительно индекс (3136 дневных
  значений в диапазоне 0–100 с 2018 года), а остальные графики за этот диапазон выходят.

Оба ответа прогоняются через весь бот до готового стартового сообщения:

```bash
go test -run RealAlternativeResponse -v .
go test -run RealCoinGlassResponse -v .
```

## Если CoinGlass поменяет сайт

Касается только `source: coinglass`. Сайт может сменить ключи или схему шифрования. Тогда
в стартовом сообщении и в логах появится ошибка вида `unsupported encryption version v="88"` или
`decrypt data ...`, а `make test-live` начнёт падать. Ключи и алгоритм лежат в
[internal/coinglass/crypto.go](internal/coinglass/crypto.go). Их можно найти в JS-бандле страницы:
функции-перехватчики axios рядом с `interceptors.response.use`. Пока исправления нет, можно
переключиться на `source: alternative`.
