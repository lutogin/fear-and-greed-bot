# Fear & Greed Telegram bot

Бот раз в N часов (по умолчанию 4) берёт два индекса страха и жадности и пишет в Telegram, когда
какой-то из них доходит до заданных уровней:

- **крипто**: Crypto Fear & Greed Index (alternative.me или CoinGlass);
- **акции США**: [CNN Fear & Greed Index](https://edition.cnn.com/markets/fear-and-greed).

Пороги у индексов свои. Повторные уведомления подавляются: по одной стороне (fear/greed) одного
индекса не чаще раза в `cooldown` (по умолчанию 2 дня).

Один статический бинарник около 7 МБ, из зависимостей только YAML-парсер.

## Откуда берутся данные

Источник каждого индекса задаётся ключом `source` в его секции конфига.

### Крипто (`crypto.source`)

**`alternative` (по умолчанию)**: [alternative.me](https://alternative.me/crypto/fear-and-greed-index/),
официальный бесплатный API без ключа: `GET https://api.alternative.me/fng/?limit=1`
([internal/alternative](internal/alternative)). Индекс обновляется раз в сутки (в 00:00 UTC).
Правила API требуют указывать источник рядом с данными, поэтому в каждом сообщении бота есть строка
«Данные alternative.me на …» со ссылкой.

**`coinglass`**: [индекс CoinGlass](https://www.coinglass.com/pro/i/FearGreedIndex). Их официальный API
(`open-api-v4.coinglass.com/api/index/fear-greed-history`) требует ключ `CG-API-KEY` и доступен только
на платных тарифах, поэтому бот читает данные страницы. В HTML значения нет: браузер загружает его
JavaScript-ом из `capi.coinglass.com/api/index/history`, и ответ зашифрован (AES-ECB + zlib, ключ
выводится из заголовков ответа). Бот делает тот же запрос, что и страница, и расшифровывает ответ
тем же алгоритмом, что и её JS ([internal/coinglass](internal/coinglass)). Способ неофициальный:
если сайт поменяет шифрование, бот перестанет его читать (см. ниже). Индекс обновляется раз в сутки
(около 00:20 UTC).

Это два разных индекса с разной методикой и разными границами зон (Fear, Greed и т. д.), поэтому
значения у источников не совпадают. При смене источника стоит перепроверить пороги.

### Акции США (`stocks.source`)

**`cnn` (единственный вариант)**: [CNN Fear & Greed Index](https://edition.cnn.com/markets/fear-and-greed)
по рынку акций США. Официального API у CNN нет: страница берёт индекс из JSON
`GET https://production.dataviz.cnn.io/index/fearandgreed/graphdata`, и бот делает тот же запрос
([internal/cnn](internal/cnn)). Ключ не нужен, но запросы без браузерного `User-Agent` эндпоинт
отклоняет с HTTP 418, поэтому бот представляется браузером. Значение (`score`) приходит дробным,
бот округляет его до целого, как на странице, и с этим числом сравнивает пороги. Индекс обновляется
в течение торгового дня, в выходные не меняется. Сама страница edition.cnn.com открывается не из
всех стран (бывает HTTP 451), но на эндпоинт с данными это не влияет.

## Быстрый старт

1. Создайте бота у [@BotFather](https://t.me/BotFather) и получите токен.
2. Узнайте `chat_id`: напишите боту любое сообщение и откройте
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates`, нужное поле `chat.id`. Для канала подойдёт `@имя_канала`,
   бот должен быть администратором канала.
3. Настройте конфиг:
   ```bash
   cp config.example.yaml config.yaml
   ```
4. Соберите бота и проверьте связку «источники индексов → Telegram»:
   ```bash
   make build
   ./fngbot -config config.yaml -test-message
   ```
5. Запустите:
   ```bash
   ./fngbot -config config.yaml
   ```

Флаги:

| Флаг | Что делает |
|---|---|
| `-config path` | путь к конфигу, по умолчанию `config.yaml` |
| `-once` | одна проверка и выход, без сообщения о старте; удобно для cron |
| `-test-message` | отправить в Telegram текущие значения индексов и выйти |

## Конфигурация

Все параметры с комментариями описаны в [config.example.yaml](config.example.yaml).

```yaml
interval: 4h            # как часто проверять; понимает и дни: 1d, 1d12h
crypto:                 # крипто; удалите секцию, чтобы не следить за индексом
  source: alternative   # alternative (alternative.me) или coinglass
  alerts:
    fear: [20]          # уведомить, если индекс <= 20
    greed: [80]         # уведомить, если индекс >= 80
stocks:                 # акции США
  source: cnn
  alerts:
    fear: [25]
    greed: [75]
dedup:
  cooldown: 2d          # не чаще раза в 2 дня по каждой стороне каждого индекса
  storage: file         # file (переживает рестарт) или memory
  file: data/state.json
telegram:
  bot_token: "..."      # или переменная окружения TELEGRAM_BOT_TOKEN
  chat_id: "..."        # или TELEGRAM_CHAT_ID
```

Секции `crypto` и `stocks` необязательны, но хотя бы одна нужна. В секции должен быть хотя бы один
уровень. Старый формат с `source` и `alerts` на верхнем уровне больше не читается: бот при старте
попросит перенести их в секцию `crypto`. Записи cooldown из файла состояния старой версии (ключи
`fear` и `greed`) новая версия не учитывает, поэтому сразу после обновления алерт по крипте может
прийти повторно.

Переменные окружения `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` имеют приоритет над файлом,
так что секреты можно в конфиге не хранить. Опечатки в ключах конфига считаются ошибкой.

## Когда приходит уведомление

- При запуске (без `-once`) бот сразу проверяет оба индекса и присылает сообщение о старте: текущие
  значения, пороги каждого индекса, время следующей проверки и паузу между повторами. По текущим
  значениям видно, что источники читаются правильно; их можно сверить с сайтами. Если какой-то
  индекс получить не удалось, вместо его значения в сообщении будет ошибка. Алерты по первой
  проверке, если они нужны, приходят следом. Если Telegram в этот момент недоступен, бот пишет
  предупреждение в лог и продолжает работу.
- В уведомлении в заголовке указано, какой индекс достиг порога: «Крипто» или «Акции США».
- Уровни включительные: `fear: [20]` срабатывает при индексе 20 и ниже, `greed: [80]` при 80 и выше.
- На каждую сторону можно задать несколько уровней (`fear: [25, 10]`). В уведомлении указывается
  самый глубокий достигнутый уровень.
- Cooldown считается отдельно для каждого индекса и для страха и жадности: если рынок резко
  развернулся, вы об этом узнаете, а алерт по крипте не глушит алерт по акциям.
- В пределах cooldown повторов нет. Исключение: индекс дошёл до более глубокого уровня той же стороны
  (например, после уведомления о `≤ 25` индекс упал до `≤ 10`). Откат назад к `≤ 25` новое
  уведомление не вызывает.
- Время последней отправки хранится в JSON-файле (`dedup.file`) с ключами вида `crypto.fear`,
  `stocks.greed`. Файл пишется атомарно, поэтому перезапуск или запуск через cron с `-once` не
  приводит к повторной отправке.
- Если Telegram или источник индекса недоступны, проверка этого индекса повторяется через 5 минут,
  а не через `interval`; второй индекс проверяется по своему расписанию. Неотправленное уведомление
  не запускает cooldown.

Сообщение о старте:

```
🚀 Fear & Greed бот запущен

🪙 Крипто: 71 (Greed)
Данные alternative.me на 25.09.2026 00:00 UTC
Пороги: страх ≤ 20 · жадность ≥ 80

📈 Акции США: 40 (Fear)
Данные CNN на 12.11.2026 21:43 UTC
Пороги: страх ≤ 25 · жадность ≥ 75

Проверка индексов: с интервалом 4 часа, следующая 13.11.2026 02:08 UTC
Пауза между повторными уведомлениями: 2 дня
```

Уведомления о пороге:

```
😱 Крипто — Fear & Greed Index: 18 (Extreme Fear)
Достигнут ключевой уровень страха: ≤ 20
Данные alternative.me на 25.09.2026 00:00 UTC
```

```
🤑 Акции США — Fear & Greed Index: 78 (Extreme Greed)
Достигнут ключевой уровень жадности: ≥ 75
Данные CNN на 12.11.2026 21:43 UTC
```

Названия источников в сообщениях — ссылки на страницы индексов. С `crypto.source: coinglass` там
будет CoinGlass, а перед этой строкой ещё и цена BTC.

## Docker

```bash
cp config.example.yaml config.yaml      # секреты можно оставить пустыми
printf 'TELEGRAM_BOT_TOKEN=...\nTELEGRAM_CHAT_ID=...\n' > .env
docker compose up -d --build
```

Образ собирается `FROM scratch` и содержит только бинарник и CA-сертификаты. Процесс работает
от пользователя `nobody`, поэтому `config.yaml` должен быть доступен на чтение всем (`chmod 644`),
а секреты лучше передавать через `.env`. Состояние дедупликации хранится в томе `fngbot-data`.

## Тесты

```bash
make test        # go test -race ./...
make test-live   # по одному реальному запросу к alternative.me, coinglass.com и CNN
```

Unit-тесты работают без сети: источники индекса и Telegram подменяются локальными
`httptest`-серверами. Покрыты:

- все три клиента: ответы, ошибки API и HTTP; для CoinGlass ещё и расшифровка всех известных версий `v`;
- пороги, cooldown и эскалация, независимость индексов друг от друга;
- файловое хранилище: рестарт, атомарная запись, битый файл;
- клиент Telegram, в том числе то, что токен не попадает в логи;
- разбор конфига;
- сквозные сценарии `main`: стартовое сообщение с двумя индексами, алерты после него, сбой одного
  из источников, повторные запуски через `-once`.

Разбор ответов проверяется на реальных ответах источников из [testdata](testdata):

- **alternative.me, 25.09.2026**: бот получает 71 (Greed) на 25.09.2026 00:00 UTC.
- **CoinGlass, 24.09.2026**: страница тогда показывала 72 (Greed), и бот получает то же значение,
  дату и цену BTC. Проверяется и вся история: первый график действительно индекс (3136 дневных
  значений в диапазоне 0–100 с 2018 года), а остальные графики за этот диапазон выходят.
- **CNN, 12.11.2026**: `score` 39.94 (fear), бот получает 40 (Fear) на 12.11.2026 21:43 UTC.

Ответы прогоняются через весь бот до готового стартового сообщения:

```bash
go test -run RealAlternativeResponse -v .
go test -run RealCoinGlassResponse -v .
go test -run StartupMessageWithBothIndexes -v .
```

## Если CoinGlass поменяет сайт

Касается только `crypto.source: coinglass`. Сайт может сменить ключи или схему шифрования. Тогда
в стартовом сообщении и в логах появится ошибка вида `unsupported encryption version v="88"` или
`decrypt data ...`, а `make test-live` начнёт падать. Ключи и алгоритм лежат в
[internal/coinglass/crypto.go](internal/coinglass/crypto.go). Их можно найти в JS-бандле страницы:
функции-перехватчики axios рядом с `interceptors.response.use`. Пока исправления нет, можно
переключиться на `crypto.source: alternative`.

## Если CNN закроет эндпоинт

Касается только индекса акций. Если CNN начнёт отклонять запросы (HTTP 418/403) или поменяет формат,
ошибка появится в стартовом сообщении и в логах, а крипто-индекс продолжит работать. Пока
исправления нет, секцию `stocks` можно убрать из конфига.
