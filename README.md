# Fear & Greed Telegram bot

Бот раз в N часов (по умолчанию 4) берёт [Crypto Fear & Greed Index с CoinGlass](https://www.coinglass.com/pro/i/FearGreedIndex)
и пишет в Telegram, когда индекс доходит до заданных уровней страха или жадности.
Повторные уведомления подавляются: по одной стороне (fear/greed) не чаще раза в `cooldown` (по умолчанию 2 дня).

Один статический бинарник около 7 МБ, из зависимостей только YAML-парсер.

## Откуда берутся данные

Официальный API CoinGlass (`open-api-v4.coinglass.com/api/index/fear-greed-history`) требует ключ
`CG-API-KEY`, а этот эндпоинт доступен только на платных тарифах (от Hobbyist). Поэтому бот читает
данные страницы.

В HTML страницы значения индекса нет: браузер загружает его JavaScript-ом из
`capi.coinglass.com/api/index/history`, и ответ зашифрован (AES-ECB + zlib, ключ выводится из
заголовков ответа). Бот делает тот же запрос, что и страница, и расшифровывает ответ тем же алгоритмом,
что и её JS ([internal/coinglass](internal/coinglass)). Headless-браузер для этого не нужен.

Индекс на CoinGlass обновляется раз в сутки (около 00:20 UTC).

## Быстрый старт

1. Создайте бота у [@BotFather](https://t.me/BotFather) и получите токен.
2. Узнайте `chat_id`: напишите боту любое сообщение и откройте
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates`, нужное поле `chat.id`. Для канала подойдёт `@имя_канала`,
   бот должен быть администратором канала.
3. Настройте конфиг:
   ```bash
   cp config.example.yaml config.yaml
   ```
4. Соберите бота и проверьте связку «CoinGlass → Telegram»:
   ```bash
   make build
   ./fngbot -config config.yaml -test-message
   ```
5. Запустите:
   ```bash
   ./fngbot -config config.yaml
   ```

Флаги:

| Флаг | Что делает |
|---|---|
| `-config path` | путь к конфигу, по умолчанию `config.yaml` |
| `-once` | одна проверка и выход, без сообщения о старте; удобно для cron |
| `-test-message` | отправить в Telegram текущее значение индекса и выйти |

## Конфигурация

Все параметры с комментариями описаны в [config.example.yaml](config.example.yaml).

```yaml
interval: 4h          # как часто проверять; понимает и дни: 1d, 1d12h
alerts:
  fear: [20]          # уведомить, если индекс <= 20
  greed: [80]         # уведомить, если индекс >= 80
dedup:
  cooldown: 2d        # не чаще раза в 2 дня по каждой стороне
  storage: file       # file (переживает рестарт) или memory
  file: data/state.json
telegram:
  bot_token: "..."    # или переменная окружения TELEGRAM_BOT_TOKEN
  chat_id: "..."      # или TELEGRAM_CHAT_ID
```

Переменные окружения `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` имеют приоритет над файлом,
так что секреты можно в конфиге не хранить. Опечатки в ключах конфига считаются ошибкой.

## Когда приходит уведомление

- При запуске (без `-once`) бот сразу проверяет индекс и присылает сообщение о старте: текущее
  значение, пороги, время следующей проверки и паузу между повторами. По текущему значению видно,
  что сайт читается правильно; его можно сверить со страницей CoinGlass. Если индекс получить
  не удалось, вместо значения в сообщении будет ошибка. Алерт по первой проверке, если он нужен,
  приходит следом. Если Telegram в этот момент недоступен, бот пишет предупреждение в лог
  и продолжает работу.
- Уровни включительные: `fear: [20]` срабатывает при индексе 20 и ниже, `greed: [80]` при 80 и выше.
- На каждую сторону можно задать несколько уровней (`fear: [25, 10]`). В уведомлении указывается
  самый глубокий достигнутый уровень.
- Cooldown считается отдельно для страха и для жадности: если рынок резко развернулся, вы об этом узнаете.
- В пределах cooldown повторов нет. Исключение: индекс дошёл до более глубокого уровня той же стороны
  (например, после уведомления о `≤ 25` индекс упал до `≤ 10`). Откат назад к `≤ 25` новое
  уведомление не вызывает.
- Время последней отправки хранится в JSON-файле (`dedup.file`). Файл пишется атомарно, поэтому
  перезапуск или запуск через cron с `-once` не приводит к повторной отправке.
- Если Telegram или CoinGlass недоступны, проверка повторяется через 5 минут, а не через `interval`.
  Неотправленное уведомление не запускает cooldown.

## Docker

```bash
cp config.example.yaml config.yaml      # секреты можно оставить пустыми
printf 'TELEGRAM_BOT_TOKEN=...\nTELEGRAM_CHAT_ID=...\n' > .env
docker compose up -d --build
```

Образ собирается `FROM scratch` и содержит только бинарник и CA-сертификаты. Процесс работает
от пользователя `nobody`, поэтому `config.yaml` должен быть доступен на чтение всем (`chmod 644`),
а секреты лучше передавать через `.env`. Состояние дедупликации хранится в томе `fngbot-data`.

## Тесты

```bash
make test        # go test -race ./...
make test-live   # один реальный запрос к coinglass.com
```

Unit-тесты работают без сети: CoinGlass и Telegram подменяются локальными `httptest`-серверами.
Покрыты расшифровка (все известные версии `v`), пороги, cooldown и эскалация, файловое хранилище
(рестарт, атомарная запись, битый файл), клиент Telegram (в том числе то, что токен не попадает
в логи), разбор конфига и сквозные сценарии `main`: стартовое сообщение, алерт после него,
повторные запуски через `-once`.

Правильность парсинга проверяется на реальном ответе CoinGlass от 24.09.2026
([testdata](testdata/coinglass_history_2026-09-24.json)). Страница тогда показывала 72 (Greed),
и бот получает то же значение, дату и цену BTC. Кроме того, проверяется вся история: первый
график действительно индекс (3136 дневных значений в диапазоне 0–100 с 2018 года), а остальные
графики за этот диапазон выходят, так что перепутать их нельзя. Тот же ответ прогоняется через
весь бот до готового стартового сообщения:

```bash
go test -run RealResponse -v .
```

## Если CoinGlass поменяет сайт

Сайт может сменить ключи или схему шифрования. Тогда в логах появится ошибка вида
`unsupported encryption version v="88"` или `decrypt data ...`, а `make test-live` начнёт падать.
Ключи и алгоритм лежат в [internal/coinglass/crypto.go](internal/coinglass/crypto.go). Их можно
найти в JS-бандле страницы: функции-перехватчики axios рядом с `interceptors.response.use`.
